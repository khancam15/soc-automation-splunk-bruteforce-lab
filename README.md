## 🛡️ SOC Automation & Detection Engineering Lab

### SMB Brute Force Simulation → Splunk Detection → Automated Case Triage

---

## 🔍 Overview

This lab simulates a real-world SMB brute-force attack in a controlled virtual environment, detects it using Splunk, and automates case note generation using the Splunk REST API and Python. The goal is to demonstrate end-to-end SOC analyst workflow: from threat simulation to detection engineering to alert triage documentation.

---

## 🧰 Tools & Technologies

| Tool | Purpose |
|---|---|
| Kali Linux | Attacker machine — SMB brute-force simulation |
| Windows 11 VM | Target machine |
| Splunk Enterprise | Log ingestion, detection, and alerting |
| Splunk Universal Forwarder | Windows event log forwarding |
| Python 3 | Automated case note generation via REST API |
| VirtualBox | Virtualization (Host-only + NAT networking) |
| Hydra | SMB brute-force tool |

---

## 🏗️ Lab Architecture

```
[Kali Linux VM] ---(Host-only Network)---> [Windows 11 VM]
                                                  |
                                    [Splunk Universal Forwarder]
                                                  |
                                    [Splunk Enterprise (indexer)]
                                                  |
                                        [Python REST API Client]
                                                  |
                                        [Automated Case Notes]
```

---

## 🎯 Lab Objectives

- Simulate an SMB brute-force attack from Kali Linux targeting a Windows 11 host
- Configure Splunk Universal Forwarder to ship Windows Security Event Logs (Event ID 4625)
- Build a Splunk detection query to identify brute-force behavior
- Use Python and the Splunk REST API to programmatically pull alert data
- Auto-generate structured case notes for SOC triage
